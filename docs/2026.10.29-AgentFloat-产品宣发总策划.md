## 0. 一句话结论

**不要把 4.0 当宣传主题，把 4.0 当发射窗口。**

- **产品主张**：一个浮球，装下你的 AI 工作台。
- **品类**：多 Agent 桌面工作站。
- **4.0 的角色**：第一次把「启动 / 进度 / Skills / 快报」四件事连成一体，是证明，不是标题。
- **宣传对象**：不只是现有用户，而是更广阔的「同时用多个 AI 工具」的人。
- **平台**：B站、官网、GitHub、朋友圈、微信贴图号；小红书/抖音/知乎/公众号/少数派按产能后置。

## 1. 为什么不能按「版本宣传」做

版本宣传的典型写法：

> 4.0 来了：新增 Agent Hub、进度面板、Skill 车间、AI 日报 2.0……

这只对已经关心 AgentFloat 的人有效。对更广阔的平台，用户第一反应是：

> 「这跟我有什么关系？」

产品宣传要反过来：

> 你同时开几个 AI？窗口是不是越开越多？谁卡住了你知道吗？
> 有一颗浮球，能把它们收在一起。

**4.0 只在后面出现：**

> AgentFloat 4.0 全面大升级，第一次把启动、进度、Skills、快报装进同一颗球。

版本是证据，痛点是入口，产品是主角。

## 2. 产品定位

### 2.1 一句话

**大众版：**

> **一个浮球，装下你的 AI 工作台。**

**品类版：**

> **AgentFloat：多 Agent 桌面工作站。**

**功能版：**

> 启动 AI、看进度、装 Skills、读快报——都在桌面这一颗球上。

### 2.2 它不是什么

- 不是另一个 AI 聊天工具。
- 不是只负责“启动”的快捷方式。
- 不是 IDE，也不是 Agent 本身。
- 它是桌面上的 **AI 调度层 / 状态层 / 入口层**。

### 2.3 替代方案

| 现在怎么做 | 问题 | AgentFloat 的差异 |
|---|---|---|
| 手动开一堆窗口 / 终端 | 找不到、切到晕、不知道谁卡住 | 一颗浮球统一启动 + 状态雷达 |
| 只用某个 IDE 或 Agent 自带 UI | 只看到一个 Agent，跨工具就断 | 跨 Agent 的桌面层，不绑定单一模型 |
| 用启动器 / 快捷方式 | 只能启动，不能看进度、管 Skill | 启动 + 进度 + Skill + 快报 |
| 什么都不管，靠记忆 | 注意力被切碎，任务漏掉 | 需要你时自动置顶 + 提醒 |

## 3. 卖点包装

| 功能 | 用户利益 | 传播句 | 证据 |
|---|---|---|---|
| **Agent 启动** | 不用找图标、记命令、开终端 | 「一个浮球，启动你常用的 AI」 | 18+1 目录、检测/安装/启动/更新 |
| **进度条** | 不切窗口就知道谁在跑、谁卡住、谁等你 | 「抬眼就知道，谁在等你」 | L0 雷达条 / L1 快面板 / L2 驾驶舱、ETA |
| **Skills 车间** | 不用手动拷目录、折腾配置 | 「装 Skill，像装 App 一样」 | 发现、预览、固定 commit、逐 Agent 回滚 |
| **AI 快报** | 不用刷十个源，3 分钟看完 | 「每天 3 分钟，AI 大事不漏」 | 15 源、评分、AI 摘要/翻译 |
| **浮球形态** | 不占任务栏、不抢焦点、随手可用 | 「桌面常驻，但不打扰」 | Qt 浮球、贴边、低干扰 |
| **本地优先** | 进度、配置、密钥留在本机 | 「你的工作状态，不该上云」 | 本地状态文件、可回滚、默认不执行脚本 |

**统一收口：**

> 启动、进度、Skills、快报——四个后台，一颗浮球。

## 4. Campaign 主张

### 4.1 主主张（推荐）

> **一个浮球，装下你的 AI 工作台。**

理由：有画面、有品类、有产品形态；不依赖“4.0”这个数字；对泛 AI 用户也能一眼看懂。

### 4.2 备选主张

| 主张 | 适合 | 风险 |
|---|---|---|
| **你的 AI 们，需要一个总控台** | 知乎/公众号/官网 | 偏理性，画面感弱 |
| **AI 工具越装越多，桌面需要一颗球** | 小红书/抖音 | 句子长，适合做封面标题 |
| **别再 Alt-Tab 了，让 AI 自己汇报进度** | B站/开发者 | 偏开发者，泛用户门槛高 |

### 4.3 三层文案

**15 秒（短视频）：**

> 同时开 3 个 AI，谁卡住了？
> 一颗浮球，全部看见。
> AgentFloat 4.0，全面大升级。

**30 秒（官网/朋友圈）：**

> 你有没有这种桌面：Claude、Codex、OpenCode 各开一个窗口，切来切去，还是不知道谁在等你。
> AgentFloat 把启动、进度、Skills、快报收进一颗浮球。
> 一个浮球，装下你的 AI 工作台。

**3 分钟（B站；公众号/知乎后置）：**

> 这不是又一个 AI 工具。这是一个桌面层：让多个 AI 在同一个地方启动、汇报、被管理。
> 4.0 是第一次把四件事连起来：Agent Hub、进度雷达、Skill 车间、AI 快报。

### 4.4 4.0 的位置

- 标题不写「4.0 发布」，写产品主张。
- 4.0 作为角标/副标题：**「4.0 全面大升级」**。
- 发布日可以有一篇「4.0 更新说明」，但它不是 campaign 主文。

## 5. 受众与场景

| 人群 | 场景 | 入口内容 |
|---|---|---|
| **多 AI 工具使用者** | 同时开 Claude / Codex / OpenCode / dsh，或几个 AI 窗口轮着用 | 「同时开 3 个 AI，怎么知道谁卡住？」 |
| **多项目知识工作者** | 写作、研究、运营、开发并行 | 「把工作记忆外置成一条雷达」 |
| **内容创作者 / 研究者** | 多个 AI 帮忙查资料、写稿、做图 | 「AI 快报 + 多任务进度」 |
| **独立开发者** | 一个人当一支队伍 | 「一个人，也要有总控台」 |
| **现有 AgentFloat 用户** | 已经在用浮球启动 Agent | 「4.0 把启动器升级成工作站」 |

**首发切口**：不要一上来讲 MCP/CLI/Agent 协议；先讲「窗口太多、不知道谁在干活」。技术细节放到 GitHub、B站长视频；公众号/知乎长文后置。

## 8. 节奏

> 不公布日期；按「内容资产 + 产品门」推进。

| 阶段 | 目标 | 内容 | 产出 |
|---|---|---|---|
| **P0 种子** | 积累共鸣 | 开发日志、问题征集、内测预约 | 20 条用户原话 |

- 预热期：B站每周 1 条；微信贴图号每周 2–3 条；朋友圈每周 1 条。

### 9.3 视频制作方式

用 **hyperframes** 生成网页视频，再混入真实产品录屏；不先拍真人。

1. 先做 storyboard：15 秒竖屏 / 60 秒横屏 / 3–5 分钟 B站版各一条时间轴。
2. 主画面：浮球 + 四个轨道图标 + L0/L1/L2 状态切换；3 个项目出现 → 一个变黄 → 点开快面板 → 回到 L0。
3. 真实产品段落：Agent Hub 安装、Skill 车间安装、AI 快报打开，用录屏补可信度。
4. 输出 16:9 与 9:16 两套画布；B站版保留技术细节，微信贴图号版只留痛点与结果。

## 10. 漏斗与指标

```text
看到（B站/微信贴图号/朋友圈）
  → 感兴趣（官网/预约）
  → 下载/内测
  → 首次启动
  → 用起来（L0/Skill/快报）
  → 留下来（7 日/30 日）
```

| 层级 | 指标 | 说明 |
|---|---|---|
| 曝光 | 播放、阅读、收藏、评论 | 平台后台 |

| 转化 | 下载、安装、首次启动 | 下载页/本地匿名计数 |
| 激活 | 添加 Agent、L0 出现、打开一次快报 | 本地事件 |
| 留存 | 7 日/30 日再次启动 | 本地匿名计数 |
| 口碑 | GitHub Star、Issue、推荐意愿 | GitHub/反馈表 |

**先定基线，再定目标。** 不拍脑袋写「下载 1 万」。
