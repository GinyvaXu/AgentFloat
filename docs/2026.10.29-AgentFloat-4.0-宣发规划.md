## 0. 结论先行

4.0 的宣发不要按「功能更多」讲，按 **「你同时开几个 AI 干活，终于不用来回切窗口了」** 讲。

- **旗舰**：D 进度中枢（L0 雷达条 / L1 快面板 / L2 驾驶舱）。这是最强记忆点，也是和普通启动器拉开差距的地方。
- **支撑**：A Agent Hub（18+1 目录、安装/启动/更新）、C Skill 车间（发现/安装/回滚）、B AI 日报 2.0（15 源、评分、AI 摘要）。
- **开发中策略**：先做问题教育 + 开发日志 + 内测预约，不公布日期；D 三层可演示后再发第一波预热。
- **Release-ready 定义**：D 三层完成 + UI P0 修完 + 安装/升级链路通过 + 发布包（视频/截图/落地页/Release Notes/社媒草稿）全部备好。具备后，你一句话即可发。
- **发布门槛**：G-A/B/C/D + G-regress/upgrade/docs 通过；D 三层未完成，不建议发 4.0。

## 1. 目标与受众

### 1.1 宣发目标

1. 让目标用户记住一句话：**「谁在跑、做到哪、还要多久、谁需要我。」**
2. 把「AgentFloat = 多 Agent 工作站」立住，不再只是「会启动 Agent 的浮球」。
3. 为正式版拿到第一批真实下载、首次启动、7 日留存和反馈，不追求一次性大流量。

### 1.2 主受众

首发口径是「泛 AI 用户」，但落地切片必须是 **已经在同时用 2 个以上 AI 工具的人**。完全不使用 Agent 的小白，不作为首发转化目标。

| 优先级 | 人群 | 他们的场景 | 对他们说什么 |
|---|---|---|---|
| P0 | 泛 AI 用户中的「多工具使用者」 | 同时开 Claude、Codex、OpenCode、dsh，或几个 AI 窗口轮着用 | 「不用来回切窗口，抬眼就知道谁在跑、谁卡住、谁等你」 |
| P1 | 多任务知识工作者 / ADHD 用户 | 多项目并行，注意力被切碎 | 「把工作记忆外置成一条雷达」 |
| P2 | 现有 AgentFloat 用户 | 已经用浮球启动 Agent | 「4.0 把启动器升级成工作站」 |

**暂不作为首发转化目标**：只用一个聊天窗口的普通用户、企业采购、需要云端团队协作的客户。

## 2. 信息屋

### 2.1 核心句

**大众版（微信贴图号 / 朋友圈 / B站封面）：**

> **同时开几个 AI 干活，终于不用来回切窗口了。**

**产品版（官网 Hero / GitHub / Release）：**

> **AgentFloat 4.0：把多个 AI Agent 的工作状态，收进一颗浮球。**

副句：

> 谁在跑，做到哪，还要多久，谁需要你——抬眼可见。

### 2.2 四个支撑点

| 支柱 | 一句话 | 证据 |
|---|---|---|
| **看得见** | L0 雷达条、L1 快面板、L2 驾驶舱 | 3 个项目并行、need_input 置顶、ETA 区间 |
| **装得上** | Agent Hub 统一检测、安装、启动、更新 | 18+1 目录；winget/npm/pip/脚本/下载五种方式 |
| **管得住** | Skill 车间发现、预览、安装、回滚 | 固定 commit、逐 Agent 备份、许可证可见 |
| **读得完** | AI 日报 2.0 多源、评分、摘要、翻译 | 15 源、三栏阅读、源健康 |

### 2.3 信任点

- 本地优先：进度、配置、密钥留在本机。
- 安装可回滚：预览、备份、失败恢复。
- 默认不执行仓库脚本：README 注入不执行。
- 不伪造进度：拿不到计划只显示「活跃/停滞」。

### 2.4 不说什么

- 不说「自动帮你选对 Agent / Skill」——模型选择仍是概率行为。
- 不说「支持所有 Agent 的所有安装方式」——以目录标注为准。
- 不说「替代 IDE / 替代 Agent」——AF 是状态层和启动层，不是新的模型。
- 不编用户数、增长率、竞品结论；没有数据就写「待试点」。

### 3.1 开发中（现在就能做）

- 每周或每两周一条「开发日志」，只讲一个真实问题和一个进展，不讲愿景。
- 收集 20 条「多 Agent 并行时最烦的瞬间」，作为后续文案素材。

- 不做正式版倒计时；D 没到可演示前不承诺日期。

### 3.2 D 三层可演示后的第一波

**主题**：*我同时开了 3 个 AI 干活，终于不用一个个点窗口了*

素材：

1. 15 秒竖屏：三个项目条依次出现 → 一个变黄「需要你」→ 点开快面板 → 继续任务。
2. 3 张截图：L0 三项目、L1 快面板、L2 驾驶舱。
3. 一句 CTA：「4.0 内测预约，评论区/主页」。
4. 技术版补充：MCP/CLI/skill 三个通道写同一份状态，给 GitHub 读者看。

### 3.3 Beta 阶段

- 小范围邀请，数量按你现有渠道定，不追求大。
- 反馈只问三个问题：最常用场景、最卡的地方、愿不愿意推荐。
- 证言必须经用户同意，截图打码路径/密钥/项目名。
- Beta 不公开下载页，不占 Release 资源。

### 4.0 内容角度（泛 AI 用户）

- **微信贴图号**：不讲 MCP/CLI，讲「桌面同时开 3 个 AI，怎么一眼看到谁卡住」；用前后对比图。

- **GitHub**：保留技术细节，给开发者和贡献者看；不与大众文案混用。

### 4.1 官网落地页结构

1. Hero：一句话 + 15 秒演示 +「预约内测 / 下载测试版」。

5. 对比：启动器 vs 工作站（不贬低竞品，只讲差异）。
6. 信任：本地优先、可回滚、不执行脚本。

### 4.2 GitHub README

- 第一屏：Hero GIF + 一句话 + 下载/文档。

## 7. 指标

### 7.1 先定基线，再定目标

当前没有可靠的宣发基线，不建议先拍脑袋写「下载 1 万」。发布前先埋好以下指标：

| 层级 | 指标 | 采集方式 |
|---|---|---|
| 获取 | 官网访问、下载点击、GitHub Release 下载 | 官网统计 / GitHub |
| 激活 | 首次启动完成、引导完成、添加第一个 Agent | 本地匿名计数或安装包首次运行 |
| 使用 | L0 出现、L1/L2 打开、Skill 安装、日报打开 | 本地事件（不上传内容） |
| 留存 | 7 日 / 30 日再次启动 | 本地匿名计数 |
| 质量 | 安装成功率、启动失败率、崩溃率、回滚率 | 日志 / 反馈 |
| 社区 | GitHub Star、Issue、内测转化 | GitHub / 表单 |

### 7.2 建议目标（待你确认，不是承诺）

- 下载 → 首次启动 ≥ 60%。
- 首次启动 → 添加/启动一个 Agent ≥ 50%。
- 7 日留存 ≥ 25%。
- Beta 反馈中「愿意推荐」≥ 50%。
