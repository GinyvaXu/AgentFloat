## 格式规范（请按此编辑，便于我解析）

```
- [作者] 正文｜出处
```

- 每行一条，**行首必须是 `- [`**；
- `｜` 后面是出处，**可以留空**（连同 `｜` 一起删掉）；
- 想删就**整行删除**；想改就改正文；想加就按格式加一行；
- `## 分类名` 决定该条目归到哪一类（我会按分类给不同配色）；
- 以 `>` 开头的行是注释，不会被收录；
- 想给某条加"私货权重"（出现概率更高），在行尾追加 `｜*3`（数字随意，不写就是 1）。

## AI / Agent 使用建议

### 提问与提示词
- [AgentFloat] 把"我要什么"写清楚，比把"我讨厌什么"写十条更有效。
- [AgentFloat] 一次只让 Agent 做一件事，成功率高得多。
- [AgentFloat] 给 Agent 一个可验证的完成标准，它才知道什么时候该停。
- [AgentFloat] 让它先复述一遍任务，能省下大半返工。
- [AgentFloat] 示例胜过形容词：给一段"我想要的输出长这样"。
- [AgentFloat] 需要精确格式时，直接把格式模板贴给它。
- [AgentFloat] 说清"不要做什么"，边界比目标更能减少跑偏。
- [AgentFloat] 长任务先要一个计划，再让它执行第一步。
- [AgentFloat] 让 Agent 解释它为什么这么做，比让它保证"没问题"更有用。
- [AgentFloat] 复杂需求拆成三条短消息，胜过一条千字长文。
- [AgentFloat] 需要它保持风格时，先给一句"参照这段的语气"。
- [AgentFloat] 用"如果…就…否则…"描述分支，别指望它猜。
- [AgentFloat] 明确说清"输出到哪里"：文件、终端、还是直接改代码。
- [AgentFloat] 让它先列出假设，再动手；错误往往藏在假设里。
- [AgentFloat] 想要更稳的结果，就降低单次任务的"自由度"。
- [AgentFloat] 术语不一致时，先给它一份词汇表。
- [AgentFloat] 让它用你熟悉的语言复述结论，比看代码更快判断对错。
- [AgentFloat] 要求"不确定就说不确定"，能挡掉一批自信的胡说。
- [AgentFloat] 需要创意时给三个方向；需要交付时给一个方向。
