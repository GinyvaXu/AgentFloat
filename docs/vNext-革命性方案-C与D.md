## 2. C · Skills 车间 2.0（新方案）

### 2.1 定位
**「Skill 的应用商店 + 包管理器」**：能发现、能看清、能安全装、能随时退。

### 2.2 界面（Web 为主，Qt 只做快速查看）
```
┌ 发现 ────────────────┬ 详情 ───────────────────────────┐
│ 搜索 / 分类 / 排序     │ 名称 · 来源 · 许可证 · ★热度      │
│ [GitHub 搜索][周榜]    │ README 预览（安全渲染，禁脚本）    │
│ [Awesome 精选][URL]    │ 文件树 + 体积 + 是否含脚本        │
│ ─────────────────     │ 架构图（archify，按需）           │
│ 条目卡片（因子徽章）    │ 目标 Agent 勾选（可多选）         │
│ 已装 / 可更新 / 可安装  │ [安装] [更新] [卸载] [回滚]       │
└───────────────────────┴──────────────────────────────────┘
```
- 四个发现入口并列，任一失效不影响其它；共享缓存与详情页
- 卡片至少显示两个排序因子（热度/活跃/信任/匹配）
- 安装流程：**预览 → 固定 commit → 暂存校验 → 备份 → 安装 → marker**；默认不执行仓库脚本

### 2.3 数据与事务
- `SkillEntry { repo, ref, commit, readme, tree, scripts, license, installed[] }`
- `installed[]` 按 Agent/root 记录：版本、commit、备份路径、installId
- **逐 Agent 独立回滚**：每个 root 单独备份与 marker；UI 显示「已安装 2/3」，失败 root 单独重试
- 管理所有 skill（含手动装）：手动装的不自动更新；卸载走备份/回收站，不静默删除；来源未知只允许手动处理

### 2.4 验收
- 装 3 个不同 Agent 的 skill，其中 1 个失败 → 另 2 个成功且可单独回滚
- README 注入不执行；许可证/来源可见；固定 commit 可追溯
- 卸载后可从备份恢复

## 3. D · Agent 进度中枢（新方案，4.0 第一旗舰）

### 3.1 一句话
**把「Agent 在干什么」从聊天流里抽出来，变成环境的一部分**：抬眼可见、可算时间、可一键介入。

### 3.2 三层形态（重画，不沿用旧进程面板）
| 层 | 出现方式 | 内容 | 交互 |
|---|---|---|---|
| **L0 雷达条** | 有任务 >2min 或 ≥3 步自动浮现（贴浮球侧边），全部结束 10s 收起 | 每项目一行：`● 项目 · 3/7 · 当前步 · ~18m` | 点一条展开 L1 |
| **L1 快面板** | 从 L0 就地展开，贴浮球 | 步骤列表 + ETA + 失败/需要输入 + 中断/继续/聚焦 | 不抢焦点；Esc 收起 |
| **L2 驾驶舱** | L1 里「打开驾驶舱」或手动 pin | 左项目列表 / 右详情（每步预估 vs 实际、会话、操作） | 独立窗口、可拖副屏、记忆位置 |

### 3.3 三个「革命性」新点（相对旧草案的增量）
1. **统一任务总线**：不只 Agent 会话——**安装、Skill 部署、快报生成**也接入同一进度模型；一个雷达条看全部后台任务（这是旧草案没有的）。
2. **可回放时间线**：每个任务保留步骤时间戳，L2 可回放「哪一步慢了/哪一步卡住」，为下次估算校准。
3. **注意力路由**：需要输入 / 失败 / 等待验收的任务自动置顶 + 托盘提醒一次 + 一键跳回对应窗口（不是简单通知）。

### 3.4 协议（M1 三件套）
- **MCP**：`af-mcp` 只暴露一个 `progress` 工具（plan/step/done/fail/need_input/next）
- **CLI**：`af progress ...`，与 MCP 写同一份状态
- **Skill**：`progress-protocol`（已在本机存在），优先 MCP、回退 CLI
- 状态：`%APPDATA%/AgentFloat/progress/<sessionID>.json`（原子写，QFileSystemWatcher 监听；AF 未运行也不丢）
- 兜底：只读 `opencode.db`/dsh 状态，拿不到计划只显示「活跃/停滞」，**不伪造步骤**

### 3.5 ETA（算得诚实）
- 速度投影：已完成步骤实际耗时推算，每完成一步校准
- 自适应区间：前 1–3 步给 `~20–60m`，过半收紧；数据不足显示「待估」
- 不使用 tokens/s 参与 ETA（只判断是否停滞）

### 3.6 验收（G2）
- 3 个项目并行，L0 同时显示 3 行，状态/ETA 实时
- 任一任务 need_input → 置顶 + 提醒一次 + 一键跳回
- 一周试点：ETA 命中率（±30% 内）≥70%
