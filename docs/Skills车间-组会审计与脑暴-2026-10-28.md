---

## 一句话结论

方向已经成立（榜单发现 + 多 Agent 安装 + 作用域 + 分享），但当前仍是「能演示、不能日常依赖」：**更新链路是假的、身份模型会分裂、搜索一输入就失焦、发现页只展示了三分之一**。4.0 前应集中补「装前能判断、装后能更新、坏了能回退、跨 Agent 能管理」，而不是继续加榜单和卡片。

## 一、现场实测（可复现）

| # | 现象 | 证据 | 影响 |
|---|---|---|---|
| 1 | 搜索框输入 `pdf`，实际只留下 `p`，焦点回到 `BODY` | Chromium 实测；`renderSkillsWorkshop()` 在 input 回调里整段替换 `#skillsContent` | 中文输入法基本不可用；日常检索废掉 |
| 2 | 头部写「发现 60 个条目」，页面实际只渲染 20 条 | `magazineView()` 固定 `slice(0,5)` 分类 + 每类 `slice(0,4)` | 用户以为目录只有 20 条，搜索命中被截断内容时看不到 |
| 3 | 滚到列表中段再切「发现」，仍停在中段，标题/搜索在屏幕外 | 全量重绘未重置/恢复 `scrollTop` | 每次切换都要手动滚回顶部 |

| 5 | `#/skills` 刷新会落到「设置」 | 初始化路由白名单缺 `skills`（本轮已修） | 收藏/深链不可用 |

## 二、逻辑问题（按严重度）

### P0 · 会让用户做错决定

| 问题 | 证据 | 影响 | 建议 |
|---|---|---|---|
| **更新永远装回旧 commit** | `workshop.update()` 直接复用本地扫描条目，`_perform()` 用 `entry.source.commit`（来自安装时 marker）物化；`latest_commit` 只用于展示，从不回写 | 「更新」= 重装旧版；`updateAvailable` 永远消不掉；缓存更旧时还会降级 | 更新前按 entryId 取远端最新条目，用最新 commit 物化；校验不降级；成功后回写 marker 与缓存 |
| **可更新恒为 0，因为没有生产刷新入口** | 全仓仅 `workshop.refresh_discovery()` 定义，无路由/按钮调用；`/api/skills/discover` 只读 skills.sh HTML，不写远端缓存 | 用户看到「暂无可更新」会误以为真的最新；更新体系没有地基 | 增加 `POST /api/skills/refresh`（TTL + 手动刷新），按 entryId 合并；返回 `checkedAt/warnings`，区分「没检查」与「已最新」 |
| **搜索失焦** | 见实测 1 | 检索不可用，IME 被打断 | 固定外壳（头部/搜索/tab/工具栏只渲染一次），只替换结果区；debounce 120–150ms + composition 保护 |
| **adopt 可能接管错目录、改坏 entryId** | `adopt()` 用 `inst.name`（可能是 frontmatter 名）拼路径；marker 固定写 `local:<name>` | 可能给同根另一个 Skill 写标记；条目从列表消失或多副本分裂 | ✅ 本轮已修：按真实目录名操作，沿用原 `entry_id`；仍需补身份测试 |
| **「全部卸载」永远失败** | `report.uninstall_skill()` 把 `ws.get_entry()` 返回的 `{ok,entry}` 当条目用，取不到 `installed`；前端又不检查 `ok:false` | 文件没删，toast 却提示成功 | ✅ 本轮已修：正确读 snapshot、按 agent 去重、前端检查 `ok` |

### P1 · 会造成状态不一致或误操作

| 问题 | 证据 | 影响 | 建议 |
|---|---|---|---|
| 同名 Skill 跨 Agent 条目分裂 | `scanner.py` 在生成 entryId 前把第二个同名改成 `foo (skills)`；三个同名根会撞 ID | 一个 Skill 装 4 个 Agent 变成多张卡；「一个条目 + installed[]」失效 | 先按稳定 source key 生成 ID，再单独生成 displayName；不要拿目录 basename 进 ID |
| target 以 agent 为键，多根同 Agent 会操作错目录 | `update/uninstall/set_enabled` 按 `i.agent` 找目标；scanner 还扫 `.opencode`、插件缓存等非默认根 | 更新写到另一个根，旧副本不动；卸载/启停可能动错副本 | 操作对象改为 `installId` 或真实 `path`；target 只用于新安装 |
| 部分成功被当成成功 | `jobs.py` 只有一个 `_JOB`；`ok = res.get("ok", True)`，partial 也是 true；没有 counts/targets | 2/3 失败仍提示「已安装」；无法单目标重试；两个窗口互相覆盖结果 | job 注册表 + jobId;返回 counts/每目标状态；partial 明确标 `partial:true` |
| skills.sh 安装来源写丢（已修） | `install_discovered()` 用 snake_case `entry_id/source_type`，installer 只认 camelCase | marker 变成 local，无法更新/分享 | ✅ 本轮已修：camelCase + `repo=owner/repo` + source 字典 |
| tar 只限压缩包 30MB，解压不设限 | `_safe_extract()` 对单文件/总量/数量无限制 | 30MB 可膨胀到数 GB，先写满盘再被拒绝 | 解压前按 `TarInfo.size` 限制单文件/总量/文件数 |
| slug 匹配会静默装错 | `_pick_member()` 单候选无条件返回；`slug in folder` 子串匹配 | 安装到无关 Skill；`pdf` 命中 `pdf-extractor` | 只接受 exact base / exact frontmatter name；歧义返回候选列表 |
| 发现页不合并本机安装状态 | 发现条目是另一套 entryId，无 installed 字段；目标徽标显示的是该目录总数 | 已装的仍显示可安装；`已装 19` 被误解为「这个 Skill 装了 19 次」 | 后端按 `skillssh:<source>/<slug>` 合并 installed；目标标签改成「本 Skill 已装/未装」 |
| 徽标优先级吞掉「有更新」 | `skillBadge()` 先判 installed 再判 update | 「可更新」列表里永远显示「已安装」 | ✅ 本轮已修：update 优先；建议改成状态栈（已安装 ×2 + 有更新） |
| 批量作用域忽略搜索过滤 | 统计用过滤后的 rows，批量操作读全量 cache | 搜索后点「全部停用」会停掉该 Agent 所有 Skill | 批量范围使用当前可见 ID，按钮带数量；或搜索时禁用批量 |
| 详情弹层加载无关闭/竞态 | 先开「正在读取…」，再 `await` 后无条件 `openModal`；无 seq/abort | 关闭后请求回来又弹开；连点两个 Skill 会串内容 | 加载态给关闭 + 骨架；modalSeq/AbortController；结果按 source+slug 缓存 |
| 卸载最后副本后接口报错（已修） | `workshop.uninstall()` 移动目录后再 `get_entry()` 反查 | 文件已进回收站，接口却报错 | ✅ 本轮已修：反查失败时返回 `entry:null` |
| 作用域开关样式污染设置页（已修） | `.switch` 在 216 与 683 行各定义一套，尺寸/圆点不一致 | 设置页开关圆点溢出轨道 | ✅ 本轮已修：Skills 改用 `.scope-switch` 命名空间 |

### P2 · 规模、安全与长期维护

- **索引缓存无锁**：`workshop` 每次整块读改写 `index.json`，并发刷新会丢 mode；`.bak` 切换有文件缺失窗口。
- **缓存无上限/失败也缓存**：`_SKILLSH_CACHE` 失败后仍钉 10 分钟；`_DETAIL_CACHE` 无淘汰。
- **marker 信任与路径**：`install_from_marker()` 无条件 `managed=True`（本轮已改为尊重字段）；`marker.name` 未过 `safe_skill_name()`，损坏 marker 有越界读写风险；`installId` 直接拼备份路径。
- **target 身份**：`.agents/skills` 是共享目录，卸载会影响所有读取它的 Agent，但 UI 没提示；插件缓存里 Skill 不应映射为可写 target。
- **临时目录与备份**：`.agentfloat-old-*` 清理依赖隐式路径；`cleanup_staging()` 无调用；备份无保留策略。
- **发现详情解析脆弱**：skills.sh HTML 结构一变，摘要/星标/审计就空；没有 fixture 测试。
- **更新语义**：adopted 条目 `source.type=local`，更新会直接 `no_upstream`；更新会静默把停用副本重新启用。
- **README/文件树/许可证**：后端已有 `read_readme`/`list_tree`，UI 未展示；这是「装前可信」的最低配置。
- **factors 类型**：后端是 `list[dict]`，前端按对象 `Object.keys` 取，未来有数据会算出 `NaN`。

## 三、功能拓展（脑暴收敛）

### 必须做（4.0 发布门槛）

1. **安装预检单**（S）：来源、固定 commit、许可证、是否含脚本、覆盖哪些 Agent、备份位置、可退路。所有安装入口（榜单/详情/矩阵/锁文件）复用同一张单。
2. **详情页 2.0**（M）：README（禁脚本）、文件树、许可证、固定 commit、体积；把「它做什么/优势」从摘要升级为可判断。
3. **远端更新检查器**（M）：只查受管副本；并发 ≤4、ETag、24h TTL；三态「最新 / 落后 N 个提交 / 未检查」；失败不能伪装成最新。
4. **备份时间线与恢复**（M）：备份 manifest（时间/commit/digest/大小）；恢复前再备份当前；恢复后校验 hash。
5. **Skill × Agent 矩阵**（M）：行=Skill、列=Agent，五态「未装/启用/停用/手动/落后」；点格子启停或打开预检；批量走「选中→应用」。
6. **更新执行与单目标回滚**（M）：逐目标备份→校验→换入→写 marker→复扫；失败目标可重试，不影响已成功目标。

### 高价值但可延后（4.0.x）

- 更新差异预览（commit 列表 + 变更文件 + SKILL.md 文本 diff）
- 批量更新 / 安装队列（同一 root 串行）
- 环境体检与修复（孤儿 marker、副本版本不一致、备份膨胀）
- 批量作用域撤销（快照）
- 项目技能包 / 预设（声明式 desired state，opt-in）

### 4.1 再做

- 团队锁文件 `agentfloat-skills.json`（固定 commit + 目标 + 启停状态）
- 深链 `agentfloat://skill?...`（只打开预检，不自动安装）
- 分享卡片/二维码（营销物料）
- CLI / MCP（`af skill check`，与 D 线共用任务模型）

### 明确不做

- 自建 Skill 市场（评分/评论/上传/审核）——skills.sh + GitHub 已是水源。
- 默认静默自动更新——Skill 是 Agent 行为指令，必须确认 + 可回滚。
- 云同步 / 团队 SaaS 后台——本地产品阶段，锁文件 + Git 足够。

## 四、视觉与动效

### 先修的结构问题

1. **固定工作台，只滚结果区**：头部/搜索/tab/视图按钮常驻；加载只换 body；输入不再重绘整页。
2. **状态栈徽标**：`已安装 ×2`、`有更新`、`榜单 #12`、`可安装` 组合显示，不再互斥吞信息。
3. **作用域折叠**：每个 Agent 默认最多 5 行 + 「展开全部」；路径单行省略，按钮不换行；手动项用「未接管」pill + 接管按钮，不要禁用开关。
4. **发现页编辑流**：分类头加「查看全部 25」；hero 显示排名/安装量/星标/审计；手机上 hero 单列、side 横滑。
5. **弹层收尾**：遮罩 150ms 淡入、面板 180ms 上浮；header/footer sticky；加载骨架；Esc/焦点陷阱/关闭后恢复触发按钮。
6. **安装可见化**：工具栏下 3px 进度条 + 内联 banner（Skill 名、目标、阶段）；按钮「安装中…」并禁用；开关用 `setTimeout` 链轮询，toast 去重最多 3 条。

### 动效原则

- 只在 `tab + mode` 变化时播一次入场（160–180ms，`translateY(4px)+opacity`），输入过滤不播。
- 开关做局部乐观更新，失败回滚；不要整页淡入。
- `prefers-reduced-motion` 下只保留透明度变化。
- 视图切换后 `scrollTop=0`；同视图刷新保留位置。

### 可访问性

- 卡片/榜单行改成 `<button>` 或 `role=button + tabindex`，支持 Enter/Space。
- 开关加 `aria-label="启用 {skill} 于 {target}"`、`:focus-visible` 外圈。
- 弹层加 `aria-labelledby`、焦点陷阱、关闭后焦点恢复。
- 浅色主题：`#8FBFFF`、绿色/橙色 chip、`#FF6B60` 对比度不足（实测 1.5–2.8:1），改用语义墨色。
