# AgentFloat 发布与版本策略

> 用户策略，2026-10-09 起生效。**每次版本迭代都必须遵守。**

## 一句话规则

**默认测试版**：改完 → 构建 → 装到本机 → push 源码（**仅此而已**）。
**只有用户明确说「发布正式版」**，才升级为正式版流程。

## 测试版（默认，`CHANNEL = "beta"`）

| 动作 | 是否执行 |
|---|---|
| 更新 `VERSION` 与 `CHANGELOG` | ✅ |
| 构建正式版/调试版/安装包（归档到 `versions/vX.Y.Z/dist/`） | ✅ |
| **本地安装最新版**（就地升级，保留配置与密钥） | ✅ **每版必做** |
| 全量测试 + 冒烟 | ✅ |
| **push 源码到 main** | ✅ |
| 打 git tag | ❌ |
| 建 GitHub Release / 上传安装包 | ❌ |
| 官网镜像同步 / 全站公告 / 首页排序 | ❌ |

补充：
- UI 版本号带「测试版」标记（`core/version.version_label()` → `v3.10.0 测试版`）：
  启动动画、侧栏、关于页、托盘提示
- **测试版每次打开都视为第一次打开**：新用户引导每次启动都会重播（`is_beta()` 时忽略
  `onboarding_done`）；其它首次体验（如 AI 自检首跑）同理
- 版本号本身保持纯数字 semver（`3.10.0`），**不要写成 `3.10.0-beta`**：
  否则后续正式版 `3.10.0` 与它版本元组相同，自动更新会判定「无新版本」而卡住用户

## 正式版（用户明确要求后）

1. 把 `src/agentfloat/core/version.py` 的 `CHANNEL` 改为 `"stable"`，并同步 CHANGELOG/README/VERSIONING
2. 重新构建（正式版标识会进入 UI 与安装包）
3. 打 tag + 建 GitHub Release 并上传安装包
4. `admin.mjs mirror trigger` 同步官网镜像 → `announce set` 挂全站公告 → 视需要置顶排序
5. push 源码（含 tag）

## 为什么这样设计

- 测试版不占用 Release 与官网资源，避免半成品出现在下载页与公告里；
- 每次安装到本机 = 每版都有真实环境验收；
- 每次当第一次打开 = 反复走查新手路径，顺带回归引导与教程；
- 版本号保持数字 = 自动更新链路（R2 镜像 + SHA256）始终可比、可升级。
