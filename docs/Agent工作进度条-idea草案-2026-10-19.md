# Agent 工作进度条 · idea 草案

> 状态：**草案（未排期）** ｜ 日期：2026-10-19 ｜ 归属：AgentFloat 能力扩展
> 来源：OpenCode 桌面端「进度条插件」实验（v0.1.0 已验证后取消，资产归档）
> 一句话：让 AgentFloat 显示**当前任务做到哪**——步骤、内容、预估时间，而不只是"运行中"。

---

## 1. 机会

Agent 干长任务时，用户只能从聊天流里判断进度：翻工具卡、看零散状态、猜还要多久。现有提示要么太粗（一个 spinner），要么太散（一串工具调用）。

想要的呈现很朴素：

- 现在做的是哪一步（**3/7**）
- 这一步在做什么（一行内容）
- 还要多久（**ETA**）
- 失败时停在哪、为什么

这正是 AgentFloat 的天然位置：它是**置顶悬浮层**，可以出现在任何窗口上方，不受目标应用扩展能力的限制。

---

## 2. 已验证的事实（2026-10-19 原型实验）

### 2.1 OpenCode 桌面端没有第三方 UI 插槽

- 桌面/网页端无渲染扩展点（上游 issue #5971；只有终端 TUI 有 `session.composer.top` 等 slot）。
- 内部 GUI-extension 机制未开放（Development builds only，无文档）。
- 官方可用通道只有四类：**会话标题、合成便签（synthetic）、工具卡状态、系统通知**。

→ 结论：在 OpenCode 插件里做不出"输入框上方的像素条"，只能做语义化呈现。

### 2.2 进度协议与状态模型成立（v0.1.0 实测）

原型实现了 `progress` 工具 + 配套技能，真机会话跑通四条路径：

- `plan`（3~7 步 + 每步 ETA）→ 计划卡
- `step`（推进 / 校准 ETA）→ 步骤卡 + 标题计数
- `done` → 完成卡 + 标题还原
- `fail` → `⚠ n/N` + 一行原因 + 失败通知（状态保留可重试）

状态机、ETA 滚动校准、标题写入/还原、状态 JSON 导出均验证通过。

→ 结论：**协议与状态模型可复用；缺的只是显示端**——而显示端正是 AgentFloat 的强项。

## 3. 产品形态（3 个候选）

### A. 悬浮进度胶囊（推荐 MVP）

挂在 AgentFloat 小球旁的一条轻量进度：

- **收起**：4px 品牌渐变细线 + `3/7`，不挡内容
- **悬停/点击**：展开面板——步骤列表（✓ / ▶ / ○）、当前步、剩余时间
- **失败**：细线转危险色 + 一行原因，点击可重试
- **完成**：绿色收束，2 秒后自动收起
- **空闲**：自动隐藏，不常驻

### B. OpenCode 专属进度条（贴输入框）

读取 OpenCode 会话状态，把进度条贴在 OpenCode 窗口的输入框上方，跟随窗口移动。更贴近原始愿望，但只服务一个应用。

### C. 通用 Agent 进度协议

把 protocol 抽成通用能力：任何 Agent / 技能都能上报 `plan / step / done / fail`，AgentFloat 作为统一渲染端。A 和 B 都是它的皮肤。

**建议路线**：A（MVP）→ B（OpenCode 适配）→ C（协议开放）。

## 4. 数据与接口（AgentFloat 侧）

### 4.1 数据源

| 方案 | 说明 | 取舍 |
|---|---|---|
| 本地 JSON 文件 | 原型已按会话导出 `sessions/<sessionID>.json` | 最简单、解耦、跨版本稳；适合 MVP |
| OpenCode HTTP API / 事件流 | 更实时，可拿到更多上下文 | 与版本耦合，后续再做 |
| AgentFloat 自带协议 | 其他 Agent 通过本地事件总线上报 | 形态 C 的目标 |

### 4.2 数据模型（沿用原型）

```json
{
  "sessionID": "ses_...",
  "status": "running | done | failed | stopped",
  "steps": [
    { "name": "读取代码", "etaMin": 3, "status": "done" },
    { "name": "实现改动", "etaMin": 10, "status": "running", "note": "改导出层" }
  ],
  "current": 1,
  "startedAt": 1792411447027,
  "updatedAt": 1792411468633,
  "pausedAt": null
}
```

### 4.3 触发与干扰控制

- 自动：任务 ≥3 步或预计 >2 分钟
- 手动：说「开进度条 / 关进度条」
- 不抢焦点（Tool 窗口 + `WA_ShowWithoutActivating`）、可鼠标穿透、空闲隐藏
- 多会话：默认跟随最近活跃会话，展开后可切换

## 5. MVP 范围与工作量

| 里程碑 | 内容 | 预估 |
|---|---|---|
| M1 | 读状态 JSON + 胶囊窗口（细线 / 计数 / 收起态） | 0.5 天 |
| M2 | 展开面板（步骤列表 + 当前步 + ETA）+ 失败/完成态 | 0.5 天 |
| M3 | 跟随 OpenCode 窗口 + 设置开关 + 真实任务自测 | 0.5 天 |

合计约 **1.5 天**（不含通用协议与多 Agent 接入）。

**非目标（v1 不做）**：暂停/跳过/拖拽排序、历史回放、跨设备同步、声音提醒。

---

## 6. 风险与开放问题

- **协议稳定性**：OpenCode 插件 API 仍会变 → 用文件格式做适配层，显示端不感知上游版本。
- **窗口跟随**：多显示器 / DPI / 全屏应用 → 只做"贴目标窗口顶部"，复用 floatball 已有的 DPR 处理。
- **干扰**：常驻会挡内容 → 默认收起为细线，可穿透，空闲隐藏。
- **隐私**：只写步骤名与 ETA，不写会话正文；文件仅在本机。
- **需要 grill 的问题**：
  1. 挂小球旁，还是贴 OpenCode 窗口？
  2. 默认收起还是默认展开？
  3. 是否只服务 OpenCode，还是直接做通用协议？
  4. 多任务并行时怎么显示（切换 / 堆叠 / 只显示最活跃）？

---

## 7. 决策记录

- 2026-10-19：用户决定**取消 OpenCode 进度条插件的全部注入**，保留构想。
- 原因：桌面端无像素级插槽，语义化呈现（标题 + 卡片）价值有限；显示端交给 AgentFloat 更合理。
- 原插件代码已归档，未删；协议、状态机、ETA 计算、通知实现均可复用。
