# 浮窗雷达 · 组会审计与优化（2026-10-29）

参会角色：产品（主持）、Qt 交互、视觉、测试、性能。

## 结论

上一版雷达“丑、跳、关不掉”的根因不是配色，而是**渲染模型错了**：1.5s 定时器无条件重建整套控件、400ms 无条件 `adjustSize + move`、旧控件 `deleteLater` 前仍可见、L0 没有关闭入口。本轮重写为“内容签名驱动 + 固定几何 + 显式关闭”。

## 现场问题（已复现）

| 现象 | 根因 | 影响 |
|---|---|---|
| 浮窗反复跳动 | `_tick()` 每 1.5s 全量重建；`_place_timer` 每 400ms `adjustSize/move` | 视觉抖动、CPU 空转、鼠标难点 |
| 文本重叠/残影 | `_clear()` 只 `deleteLater()`，旧控件在事件循环前仍显示 | 切换 L1 时出现双层文字 |
| 无法关闭 | L0 无关闭按钮；L1 只有「收起」 | 用户只能等任务结束 |
| 高度忽大忽小 | `QLayout.SetFixedSize + adjustSize` 依赖未完成的 sizeHint | 空底、裁切、二次跳位 |
| 信息层级弱 | 三条任务都是同样字重；状态只靠颜色 | need_input 不够抢眼 |
| 选中态缺失 | 展开行无背景/边框 | 不知道 L1 属于哪一条 |

## 设计决策

1. **内容签名**：只按 `sessionId/status/updatedAt/当前步/计数/问题/错误/展开状态` 判断是否重绘；签名不变时零重建、零移动。
2. **几何稳定**：宽 300px，高度按「头部 + 行数 + L1 步数」一次算好；移动仅在目标位移 >1px 时执行。
3. **可关闭**：右上角 `×`；关闭后记录当前签名，只有出现新内容才重新出现；Esc 先收 L1，再关 L0。
4. **层级**：头部「后台任务 · N」弱化；need_input 黄、failed 红、running 常规；展开行加蓝色 10% 底。
5. **L1 内聚**：步骤列表放进独立圆角块，底部「继续/重试、中断、复制 ID、收起」。
6. **不动效**：不加淡入淡出，避免新的闪烁源；`prefers` 不适用桌面，保持静态。

## 验收

- ✅ 3 任务并行：need_input → failed → running 排序正确
- ✅ 连续 10 次 `_tick`（相同内容）不重建、不移动
- ✅ 点击 × 立即隐藏；无新事件不再出现；新事件恢复
- ✅ L1 展开文字不重叠（旧控件先 hide + setParent(None)）
- ✅ 截图：`docs/radar-l0-3tasks.png`、`docs/radar-l1-3tasks.png`
- ⏳ 真实桌面长期挂机抖动观察（需一晚）
- ⏳ 双屏/DPI 缩放边界
