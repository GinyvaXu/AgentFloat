## 0.5 方案概览（v0.1 初稿）

### FreeLLMAPI 是什么

- MIT 开源自托管网关，Node 20+，Windows 有桌面 `.exe`，也支持 Docker。
- 聚合 **用户自己添加的** 34 家免费档、635 个端点，宣称约 7.4B tokens/月；统一 OpenAI 兼容 `/v1`，也支持 Anthropic Messages、Gemini、Ollama 等表面。
- 能力：智能路由、429/5xx 自动切 Key/模型、按 Key 限额跟踪、加密存储、图片/语音/嵌入、工具调用、fusion 多模型合成。
- **关键纠正**：FreeLLMAPI 本身不发放免费额度；额度来自用户自己的 Google/Groq/Mistral/OpenRouter 等账号。AF 内置软件 ≠ AF 提供免费额度。
- 官方免责声明：仅供个人实验与学习，不建议生产；上线前应换成付费 API；用户需遵守各上游 ToS。

### AF 当前需要外部 LLM 的功能

1. **AI 日报 2.0**：精选、摘要、标题/摘要翻译（`purpose=news`）。
2. **Skills 翻译**：新装 Skill 的中文名/简介补全（`purpose=translate`）。
3. **测试**：AI 接入供应商连通性（`purpose=test`）。
4. 其他（Agent 启动、进度、Skill 安装、快报抓取）不直接需要外部 LLM。

### 三种接入深度

| 方案 | 内容 | 优点 | 风险 | 建议 |
|---|---|---|---|---|
| **A 预设接入** | 在“AI 接入”里加 FreeLLMAPI 预设：`http://127.0.0.1:3001/v1` + 用户 unified key + `auto`；检测健康 | 改动小、风险低、当天可做 | 用户仍需自己装/配 FreeLLMAPI 和上游 Key | **先做** |
| **B 引导安装/随行** | AF 检测/引导安装 FreeLLMAPI 桌面版或 Node 服务，管理端口/启动/停止 | 体验更顺 | 打包、端口、更新、Node 依赖、杀软误报 | 二期 |
| **C 内置共享额度** | AF 自带 Key/共享池，让所有用户直接免费用 | 卖点最强 | 几乎必然违反上游 ToS；成本/滥用/封号 | **不做** |

### Round 1 已定（2026-11-04）

- **接入深度：A 预设接入**。AF 只加 FreeLLMAPI 供应商预设 + 健康检测；用户自己安装/运行 FreeLLMAPI，并填入自己的上游 Key。
- **接入范围：只接 AF 自身 AI**。AI 日报摘要/翻译、Skills 翻译、供应商测试；不碰 Claude Code/Codex 等外部 Agent 的配置。
- **Key 归属：用户自带**。AF 不提供共享 Key/共享额度。
- **路由顺序：一律免费优先**。所有 AF 自身 LLM 调用先走 FreeLLMAPI；失败/质量不合格再回退现有通道（CLI Agent 或付费供应商）。
- **产品文案**：写“支持接入 FreeLLMAPI / 自带 Key 的本地免费池”，不写“AF 内置免费额度”。

### Round 2 已定（2026-11-04）

- **日报质量门**：免费池结果不合格时**重试 2 次**，仍不合格再回退现有通道。
- **模型策略**：统一 `auto`，不在首版做 `auto:smart` / `auto:fast` 的用途分流。
- **未就绪行为**：自动回退现有通道 + **一次性提示**，不打断日报/翻译。
- **隐私**：首次启用 FreeLLMAPI 必须确认“内容会发往你自己配置的上游免费档”。

### Round 3 已定（2026-11-04）

- **回退顺序**：FreeLLMAPI 两次重试仍失败 → **回退 CLI Agent**；不自动切付费供应商，避免意外费用。
- **入口形态**：AI 接入页做 **FreeLLMAPI 预设卡片**，含状态、检测、打开面板、测试连接、填 Key；不内置服务。
- **对外文案**：**“支持接入 FreeLLMAPI（自带 Key）”**；不写“AF 内置免费额度”。

### 方案概览（可实施版）

```text
AF 自身 AI 功能
  ├─ AI 日报（news）
  ├─ Skills 翻译（translate）
  └─ 供应商测试（test）
        ↓
services/llm.py（统一 chat）
        ↓
FreeLLMAPI（localhost:3001/v1，model=auto）
  ├─ 成功 → 返回
  ├─ 401/未启动/429/超时/JSON 不合格 → 重试 2 次
  └─ 仍失败 → CLI Agent（现有回退）
        ↓
首次启用：隐私确认；未就绪：一次性提示
```

默认配置：

- `base_url`: `http://127.0.0.1:3001/v1`（可编辑）
- `model`: `auto`
- `api_key`: FreeLLMAPI unified key，存 Vault/环境变量，不写明文
- 健康检查：`GET /v1/models`（200/401/连接失败三态）
- 熔断：未就绪/连续失败后冷却 5 分钟，冷却期内直接走 CLI Agent，避免每次调用都重试
- 日志：记录 `X-Routed-Via` 到调试日志，不写用户正文

### 推荐初稿

先做 **A**，把 FreeLLMAPI 作为“自带 Key 的本地 OpenAI 兼容供应商”；在 `services/llm.py` 加预设，默认 `base_url=http://127.0.0.1:3001/v1`、`model=auto`，检测 `/v1/models` 与一次短 chat。失败重试 2 次，仍失败回退 CLI Agent；首次启用做隐私确认。等 A 验证有需求，再评估 B。C 不作为产品方案。

## 4. 快问快答实录

### Round 1 · 接入深度、范围、Key、路由（2026-11-04）

**Q1 “直接内置”到哪一层？**
- 选项：A 预设接入 / B 引导安装托管 / C 随 AF 分发 / D 共享额度
- 回答：**A 预设接入**
- 结论：AF 只做供应商预设与健康检测；FreeLLMAPI 由用户自己安装/运行；不把 Node 服务、端口、更新和杀软问题揽进 AF 首版。

**Q2 先接 AF 自身功能，还是也接外部 Agent？**
- 选项：A 只接 AF 自身 AI / B 也接外部 Agent / C 两者都做
- 回答：**A 只接 AF 自身 AI**
- 结论：范围锁定 AI 日报摘要/翻译、Skills 翻译、供应商测试；不修改 Claude Code/Codex 等外部 Agent 配置。

**Q3 免费档 Key 是谁的？**
- 选项：A 用户自带 / B AF 共享 / C 混合试用
- 回答：**A 用户自带**
- 结论：AF 不提供共享 Key/共享额度；产品文案不能写“AF 内置免费额度”。

**Q4 免费池和现有通道怎么排？**
- 选项：A 按用途路由 / B 一律免费优先 / C 一律质量优先
- 回答：**B 一律免费优先**
- 结论：所有 AF 自身 LLM 调用先走 FreeLLMAPI；必须补失败熔断、质量门和回退，避免日报质量被免费池拖垮。

**Round 1 脑洞**
- 把 FreeLLMAPI 做成“本地网关”分类，未来可接 LiteLLM/Ollama/LM Studio。
- 在 AI 接入页显示 `X-Routed-Via`，让用户知道这次实际由哪家免费模型服务。
- 给 FreeLLMAPI 做“AF 托管模式”：AF 只负责检测/启动/停止，Key 仍在 FreeLLMAPI 面板里填。

### Round 2 · 质量门、模型、未就绪、隐私（2026-11-04）

**Q1 日报质量不合格怎么处理？**
- 选项：修复 1 次后回退 / 重试 2 次再回退 / 不校验 / 日报不走免费池
- 回答：**重试 2 次再回退**
- 结论：免费池先试 2 次；仍不合格回退现有 CLI Agent/付费通道。需要记录重试次数与失败原因，避免无限等待。

**Q2 FreeLLMAPI 内部怎么选模型？**
- 选项：按用途 / 统一 auto / 用户手选 / 固定模型
- 回答：**统一 auto**
- 结论：首版全部交给 FreeLLMAPI 路由；不在 AF 侧做 `auto:smart` / `auto:fast` 分流，降低配置复杂度。

**Q3 FreeLLMAPI 未就绪怎么办？**
- 选项：自动回退 + 一次性提示 / 弹窗要求配置 / 直接报错 / 自动切付费
- 回答：**自动回退 + 一次性提示**
- 结论：日报/翻译不中断；托盘或面板提示一次“FreeLLMAPI 未就绪，已回退”；不自动切到可能产生费用的付费供应商。

**Q4 首次启用要不要提示数据去向？**
- 选项：首次启用必须确认 / 只在设置页说明 / 不提示
- 回答：**首次启用必须确认**
- 结论：明确告知“日报/翻译内容会发往你自己配置的上游免费档”，确认后才启用。

**Round 2 脑洞**
- 失败原因分型：未安装 / 未启动 / 401 / 429 / 超时 / JSON 不合格；不同原因给不同提示。
- 在日报生成日志里显示“免费池重试 1/2、回退 CLI Agent”，方便排查。
- 把 FreeLLMAPI 的 `X-Routed-Via` 写进调试日志，不写进用户正文。

### Round 3 · 回退、入口、文案（2026-11-04）

**Q1 FreeLLMAPI 两次重试仍失败，回退到哪？**
- 选项：回退 CLI Agent / 回退付费供应商再回退 CLI / 直接抽取式降级 / 用户选
- 回答：**回退 CLI Agent**
- 结论：不自动切付费供应商，避免用户没预期的费用；免费优先的承诺保持一致。

**Q2 AI 接入页里的 FreeLLMAPI 入口做成什么样？**
- 选项：预设卡片 + 检测/打开/测试 / 只做自定义供应商 / 引导安装向导 / 自动检测配置
- 回答：**预设卡片 + 检测/打开/测试**
- 结论：不内置服务；卡片负责状态、下载链接、打开面板、测试连接、填 Key，降低支持成本。

**Q3 对外怎么描述 FreeLLMAPI 接入？**
- 选项：支持接入（自带 Key）/ 内置本地 AI 网关 / 免费额度聚合 / 先不宣传
- 回答：**支持接入 FreeLLMAPI（自带 Key）**
- 结论：文案准确，避免“AF 提供免费额度”的误解；详情页可解释“额度来自你自己的上游免费档”。

**Round 3 脑洞**
- 卡片上做“三态灯”：未检测 / 已运行未配置 Key / 可用。
- 一键复制 FreeLLMAPI 的 unified key 到 AF，不要求用户手抄。
- 首次启用后，在日报设置里显示“当前走 FreeLLMAPI / 已回退 CLI Agent”。

## 5. 未决问题 · 风险 · 旁支灵感

### 未决

- “内置”是预设、引导安装，还是随 AF 一起分发？
- Key 是用户自己的，还是 AF 提供？
- 只接 AF 自身 AI 功能，还是也接 AF 启动的外部 Agent？
- 免费池质量不够时，回退到 CLI Agent、付费供应商，还是直接失败？
- Windows 下 Node 服务/桌面版的端口、启动、退出、更新、崩溃恢复怎么做？
- 是否需要支持 FreeLLMAPI 的 Anthropic/Gemini 表面，还是只用 OpenAI `/v1`？
- 产品文案如何避免“免费额度”误导？

### 风险

- 上游 ToS 风险：代理、共享、自动化使用可能违反条款。
- 质量风险：免费模型/额度波动，日报摘要质量不稳定。
- 稳定风险：无 SLA，晚高峰降智/429。
- 维护风险：Node 依赖、上游 provider 变化、FreeLLMAPI 版本升级。
- 安全风险：本地端口暴露、Key 存储、日志泄露。
- 信任风险：用户以为 AF 提供免费额度，实际要自己申请 Key。

### 旁支灵感

- “AI 接入”里加“本地网关”分类，不只 FreeLLMAPI，也支持 LiteLLM/Ollama/LM Studio。
- 按用途路由：日报用质量优先，翻译用免费优先。
- 一键体检：检测 FreeLLMAPI 是否在跑、Key 是否有效、哪个 provider 可用。
- 给 FreeLLMAPI 做“AF 托管模式”：AF 负责启动/停止/端口，用户只填 Key。
