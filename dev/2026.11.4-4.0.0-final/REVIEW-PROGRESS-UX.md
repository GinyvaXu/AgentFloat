## P0 阻断：must fix

### P0-1 「进度贴边条」开关保存后丢失，功能关不掉

- Finding：设置页开关写不进主进程配置，落盘又被旧快照覆盖。
- Evidence：`floatball.py:2798-2937` 的 `apply_settings` 没有 `progress` 分支，末尾 `floatball.py:2927` 用 `save_config(self.config)` 把内存配置整个写回；`server.py:233` 先写前端 cfg，紧接着 `apply_config` 触发上面这次写回。offscreen 实测：`apply_settings({...'progress':{'enabled':False}})` → `widget.config['progress'] is None`，落盘 payload 里也没有 `progress`。
- Why：这是这条贴边条**唯一的关闭入口**（面板无 ×，见 P1-2），用户改了开关，前端还会把开关打回"开"，等于白改。
- Fix：`apply_settings` 加 `if new_cfg.get("progress") is not None: self.config["progress"] = copy.deepcopy(new_cfg["progress"])`，并在此处 `radar.pause()/resume()` 或按需 `start()`；`config.py` 默认值补 `"progress": {"enabled": True}`；补一条"改开关→落盘→GET 回读仍为 false"的回归测试（与 QA 里 llm 那条同型）。

## P1 重要：affects correctness / security / UX

### P1-1 L1 明细动作行溢出，按钮文案被压没

- Evidence：offscreen 实测，5 个按钮（继续/复制 ID/聚焦/驾驶舱/收起）sizeHint 合计 254 + 16 间距 = 270，可用只有 238；实际每个被压到 40-41px（"复制 ID" 需要 75px）。4 按钮（need_input 无 window）也要 224 > 220。
- Why：主操作和"收起"都可能读不全，点击区与文字错位，是肉眼可见的破图。
- Fix：主操作最多 2 个，其余收进「更多…」；或强制两行（2+2）；或把「复制 ID / 聚焦」移到右键或驾驶舱（预览里本来就只有 2-3 个）。

### P1-2 面板没有关闭入口，Esc 实际到不了

- Evidence：头部只有「简略」「—」(`progress_radar.py:442-464`)，无 ×；`_dismiss()` 只由 `keyPressEvent` 的 Esc 触发（`400-408`），而窗口 `WA_ShowWithoutActivating` 且 `_expand` 不 `activateWindow`（`285-293`），展开后焦点不在该窗口，用户第一次点进面板内部之前 Esc 收不到。
- Why：need_input 最长可显示 4 小时，条子无法彻底收起；预览里头部是有 × 的。
- Fix：头部补 ×（调 `_dismiss`）；`_expand` 后 `setFocus()`；设置页加「重新显示进度条」以清除 `QSettings` 里的 dismissed。

### P1-3 L1 高度公式与真实内容不符：溢出出屏 / 多余留白

- Evidence：`_fit`（`363-376`）每步固定 16px、question 固定 22px。实测：1 任务 3 步内容需 207px 而固定 260px（50px 被 QVBox 拉成头尾空隙）；4 任务 + 20 步固定 688px，离屏可用高 600 → `_place` 夹到 y=0，底部 88px 出屏；无滚动条、无步数截断。
- Why：多任务+长计划时「打开驾驶舱」点不到；内容少时密度松散，头和脚被拉开。
- Fix：按内容 sizeHint 设高并 clamp 到可用高的 ~80%，明细区放 `QScrollArea`；或 steps 只显示前 6 条 + 「…还有 N 步」。

### P1-4 浅色主题（默认主题）分组与悬停不可见

- Evidence：面板底 `rgba(250,250,252,0.98)`（`412-414`），但明细块 `rgba(255,255,255,0.04)`（`528`）、简略/— hover `rgba(255,255,255,0.10)`（`448/458`）、驾驶舱按钮边 `rgba(255,255,255,0.12)`（`512`）都是白色叠白。`config.py:74` 默认 `theme: light`。
- Why：L1 明细块失去容器感，两个头部小按钮看不出可点，底部按钮像一行文字。
- Fix：按主题取叠加基色（light → `rgba(0,0,0,.04/.06/.10)`），或统一走 `tokens`/`theme` 的 SURFACE/SEPARATOR。

### P1-5 驾驶舱：回放被打断、禁用态不可辨识

- Evidence：`_timer` 1500ms → `_refresh` → `_render_selected`（`219-232`）→ `_render_steps` 删掉重建所有 StepRow（`299-315`），而回放高亮挂在旧 widget 上（`359-364`）→ 每 1.5s 高亮消失、滚动位置回顶。按钮样式 `191-197` 只写通用规则，全文件无 `:disabled` / `:focus`，而 `278-281` 大量 `setEnabled(False)`。
- Why：回放看起来"卡住"，用户以为按钮坏了；禁用按钮看起来能点，键盘 Tab 又看不到焦点。
- Fix：回放索引存状态，重建后按索引重绘高亮，回放期间暂停定时器；补 `QPushButton:disabled { color: alpha .35 }` 与 `:focus { border-color: accent }`。

### P1-6 贴边条点击目标 16×44，无悬停放大

- Evidence：`setFixedSize(16, 44)`（`137`），hover 只换背景（`145`）；预览里 `.tab:hover{width:20px}`，且条子内容为「••• / 3」两行。
- Why：16px 宽低于 24px 最小点按目标，又是贴边细条、无文字说明，第一次用基本发现不了；预览承诺的悬停反馈没落地。
- Fix：视觉保持 16px，热区扩到 24-28px（透明 padding 或外层容器），恢复 16→20 的宽度过渡，并在 need_input 时给条子加一个 3px 琥珀指示。

### P1-7 引导第 5 步：演示右键菜单压住气泡

- Evidence：`onboarding_demo("context")` → `_popup_context_menu_demo` 在球右侧 `+8` 弹出（`floatball.py:2619-2621`）；而气泡按 `GAP=26` 放在球右侧（`onboarding.py:72,88`），菜单宽约 180px，直接盖住气泡左半（标题+说明）。
- Why：这一步讲的正是右键菜单，结果菜单把讲解压在下面，用户看不清也点不到「下一步」附近内容。
- Fix：演示菜单放球左侧，或该步气泡走 `left` 方向；更好的做法是气泡内画静态菜单示意图，不弹真菜单。

## 最值得改的 3 个视觉点

1. **L1 动作行**：5 个按钮 → 1 主 + 1 次 + 「更多…」，把"复制 ID / 聚焦"降到次级；这一处是当前唯一"肉眼看出坏掉"的地方。
2. **浅色主题的容器与悬停**：明细块、头部小按钮、底部按钮全部改成黑系低透明度，否则默认主题下 L1 像"没有卡片的一堆字"。
3. **行结构对齐预览**：状态点（warn/err 微光）+ 正常色标题 + 6 段自绘进度，替掉"整行变色 + ▰▱ 字符"，扫读速度和预览一致。
